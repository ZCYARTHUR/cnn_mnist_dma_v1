# AXU15EG迁移与上板步骤

## 0. 当前状态

原项目已经在A53 Standalone中通过`0x80000000`调用4×4矩阵乘法模块，并通过串口看到PASS。现在新增CNN工程。新的同一地址将对应CNN控制接口，原有矩阵寄存器协议不再适用。

你需要本机Vivado/Vitis 2026.1、既有板卡电源/JTAG/UART连接。PuTTY继续使用COM15、115200、8N1、无流控。这一轮不用购买摄像头。

## 1. 导出原工程的板级配置

解压到`D:/FPGA/cnn_mnist_dma_v1`。在Vivado打开原`ps_hello.xpr`及其Block Design，执行：

```tcl
source D:/FPGA/cnn_mnist_dma_v1/scripts/export_board.tcl
```

脚本执行以下操作：

1. 确认原工程只有一个BD。
2. `write_bd_tcl`保存BD重建脚本，包括你已经调通的PS/DDR/UART配置。
3. 记录器件型号，复制原模块引用所需的用户HDL和用户XDC。
4. 在新包中生成`board_snapshot/`，不修改原工程。

若`board_snapshot`已经存在，脚本会停下避免覆盖；复用已有快照即可。如果原工程有更多BD、特殊include目录或外部IP仓库，应先补齐快照依赖，不能用其他板卡的DDR预设代替。

## 2. 建立CNN Vivado工程

关闭原项目，再在Vivado Tcl Console执行：

```tcl
close_project
set cnn_lanes 4
source D:/FPGA/cnn_mnist_dma_v1/scripts/create_vivado.tcl
```

如果已经通过菜单关闭了项目，省略`close_project`。新工程生成在：

```text
D:/FPGA/cnn_mnist_dma_v1/build/vivado_lanes4/cnn_mnist_dma.xpr
```

脚本导入原BD到**新工程**，删除新工程内的`matmul_axi_0`和原专用`smartconnect_0`，加入CNN模块、AXI DMA和两个SmartConnect。它保留原PS、DDR、UART和复位电路。脚本是针对你之前使用的实例名编写的：

```text
zynq_ultra_ps_e_0
rst_pl0_100M
matmul_axi_0
smartconnect_0
```

若实际名字不同，脚本明确报错，按新工程BD中的真实名称修改脚本后重新建一个新目录。不要为绕过报错删除原项目。脚本尚未在本环境的Vivado中执行，首轮要依据`validate_bd_design`诊断完成版本相关适配。

## 3. 检查连接与地址

| 起点 | 终点 | 用途 |
|---|---|---|
| PS `M_AXI_HPM0_LPD` | 控制SmartConnect `S00_AXI` | A53读写外设寄存器 |
| 控制SmartConnect `M00_AXI` | CNN `S_AXI` | CNN状态和复位 |
| 控制SmartConnect `M01_AXI` | DMA `S_AXI_LITE` | DMA长度、地址、启动 |
| DMA `M_AXI_MM2S`、`M_AXI_S2MM` | 数据SmartConnect两个输入 | 从DDR读图像和向DDR写结果 |
| 数据SmartConnect `M00_AXI` | PS `S_AXI_HP0_FPD` | 访问DDR，非一致性端口 |
| DMA `M_AXIS_MM2S` | CNN `S_AXIS` | 模型包或图像包 |
| CNN `M_AXIS` | DMA `S_AXIS_S2MM` | 分类结果包 |

在Address Editor检查：

| 外设 | A53基地址 | 软件定义 |
|---|---|---|
| CNN控制 | `0x80000000` | `CNN_CTRL_BASE` |
| AXI DMA控制 | `0xA0000000` | `CNN_DMA_BASE` |

两个DMA主接口都必须映射到PS的低地址DDR。不能只映射A53控制口而遗漏DMA到DDR的地址空间。

DMA使用Simple Mode：关闭Scatter-Gather，开启MM2S和S2MM；两个Stream均32位，内存侧64位，地址32位，长度寄存器23位；缓冲64字节对齐，因此无需DRE。DMA自身产生输入包的TLAST；CNN在结果包第12个字产生TLAST。

所有新增逻辑统一接原来的100MHz `pl_clk0`，包括DMA的三个时钟、两个SmartConnect、CNN以及PS的`saxihp0_fpd_aclk`。原`maxihpm0_lpd_aclk`也要保持连接。新增模块的低有效复位接`rst_pl0_100M/peripheral_aresetn`。不要把`pl_resetn0`当作已经同步后的外设复位直接乱接。

运行Validate Design。若提示接口频率不一致，检查PS导出时的真实`pl_clk0`频率和CNN的接口时钟属性。当前接口声明与软件默认都是100MHz。

## 4. 综合、实现与导出XSA

```tcl
source D:/FPGA/cnn_mnist_dma_v1/scripts/build_bitstream.tcl
```

脚本运行至bitstream，保存时序、资源、DRC报告，并在检测到负setup/hold slack时停止导出XSA。仍需人工查看严重DRC和未约束路径；单个正WNS不能替代完整时序检查。

成功后的目录：

```text
build/vivado_lanes4/deliverables/
  cnn_mnist_dma.xsa
  timing.rpt
  utilization.rpt
  drc.rpt
```

如果BRAM推断或时序有问题，先根据日志修改对应模块；当前`ram_style`与`use_dsp`是实现提示，最终资源必须看报告。不要写“已经用了多少DSP/BRAM”，除非报告确实给出了数字。

## 5. 建立新的Vitis Platform

使用新的工作空间，如`D:/FPGA/cnn_vitis`。创建Platform Component：

1. 名称`cnn_platform`。
2. Hardware Design选择刚生成的`cnn_mnist_dma.xsa`。
3. OS选择`standalone`，处理器`psu_cortexa53_0`。
4. 保留FSBL生成，Build平台。

检查BSP中已生成AXI DMA驱动和对应`xparameters.h`定义。若BSP只有旧矩阵工程的外设，说明选错了XSA或平台未重新生成。

## 6. 建立CNN测试应用

从Empty Application创建`cnn_test`，关联新的`cnn_platform`和Standalone域。将以下文件复制到应用的`src`：

```text
software/main.c
software/board_config.h
software/cnn_reference.c
software/cnn_reference.h
trained/cnn_test_data.h
```

保留Vitis生成的`lscript.ld`。这次一定要有`main.c`，不要再出现只有空模板、Build成功却没有ELF的情况。

核对`board_config.h`中的两个基地址。SDT平台使用DMA基地址进行`XAxiDma_LookupConfig`；旧式BSP分支使用`XPAR_AXIDMA_0_DEVICE_ID`，必要时按本机`xparameters.h`调整。

在Linker Script中将应用数据、堆栈与DMA缓冲放到低地址DDR，地址必须低于4GiB，并位于两个DMA主接口可达的DDR区域。当前DMA硬件配置只有32位地址。程序对超出32位的缓冲地址也会检查。

程序使用`printf`输出小数计时结果。选择正常newlib C库；如果改为精简库且小数打印异常，应开启浮点printf支持，或改成整数微秒输出。不要直接把格式串移到不支持`%f`的`xil_printf`。

建议Release/`-O2`构建CPU参考与DMA程序，记录实际编译选项。Build日志应包含：

```text
Linking C executable cnn_test.elf
Build Finished successfully
```

## 7. 下载并运行

PuTTY提前打开COM15。Vitis选择`cnn_test`，创建硬件Baremetal运行配置，检查：

- 目标A53核0；JTAG硬件连接可见。
- Bitstream来自新CNN XSA。
- FSBL来自新`cnn_platform`。
- 应用ELF指向`cnn_test/build/cnn_test.elf`，不能仍指向`hello_world`或`matmul_test`。

程序先读取CNN ID `0x434E4E31`，复位核心并加载模型，然后分别做单张和流水批处理。每张对比所有10个INT32 logit，不能仅以预测类别相同替代逐位校验。

结果应该包含`FINAL PASS: total mismatches=0`。首16张MNIST的识别正确数是小样本表现；完整测试集准确率请引用`trained/metadata.json`的软件评估，不能混为板上完整测试。

## 8. 首轮排错

| 现象 | 优先检查 |
|---|---|
| CNN ID不是`0x434E4E31` | 加载的bitstream/XSA是否仍是旧矩阵版本；控制基地址 |
| 读ID时卡住 | PL是否配置、时钟复位、HPM控制总线地址映射 |
| DMA初始化失败 | 新BSP是否有AXI DMA；Simple Mode/基地址是否一致 |
| DMA报错或超时 | HP0 DDR地址映射、缓冲是否在低DDR、两方向时钟、结果TLAST、缓存维护 |
| model_valid不置位 | MODEL长度必须6860字节，格式和TLAST正确，TKEEP全有效 |
| 第一帧PASS、后续失败 | 是否覆写正在被DMA读取的缓冲；是否按包重启Simple DMA；RX缓存失效 |
| 全部logit对不上 | 输入应为像素右移1；模型和参考结果是否同一套；CHW展平顺序 |
| PMU-FW提示 | 记录完整日志；此提示本身不等于CNN失败，结合FSBL启动与最终应用结果判断 |

## 9. 再比较8/16路配置

第一轮4路上板通过后关闭项目，分别设置`set cnn_lanes 8`或`16`再运行`create_vivado.tcl`。每种配置使用独立`build/vivado_lanesN`目录，复用最初的板级快照。

每次都生成对应XSA、更新或重建Vitis平台、重新下载对应bitstream，确认运行时读取的`MAC lanes`与配置一致，再记录资源和计时。不要把16路ELF的软件标签当成硬件真的变为16路。
