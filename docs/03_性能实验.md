# 性能实验与下一轮优化

## 1. 先分清已经测到什么

本次在Verilator中测得固定CNN每张图的核心周期：

| LANES | 仿真周期/张 | 若实现满足100MHz，换算核心时间 | 本次是否AXU15EG实测 |
|---:|---:|---:|---|
| 4 | 25,863 | 258.63μs | 否 |
| 8 | 23,833 | 238.33μs | 否 |
| 16 | 21,803 | 218.03μs | 否 |

上述周期不包含模型上传、图片上传、DDR争用、缓存维护、A53启动DMA或结果回传。它不能作为端到端FPS，更不能和未经测量的CPU时间计算加速比。100MHz为设计目标，须由本机实现报告证明满足。

计算可解释为：卷积与池化共19,773周期，FC每组2,030周期，FC分组数为`ceil(10/LANES)`。因此16路相对于4路只减少4,060周期。16路中多于10个输出的lane空闲；卷积阶段始终只有4路有效。这是瓶颈分析，不是所有配置都必然值得增加资源。

## 2. 板上软件报告的四项时间

`software/main.c`使用`XTime_GetTime()`计时，除第一次warm-up外默认重复10轮。计时阶段不打印每个中间结果，避免UART耗时污染结果。

| 指标 | 包含 | 不包含 |
|---|---|---|
| CPU reference mean | 可移植C卷积、量化、池化、FC及范围检查 | 图片复制、UART打印 |
| DMA+PL mean | cache flush、MM2S/S2MM提交、PL计算、等待、RX invalidate及返回检查 | 一次性模型加载、图片预拷贝、logit比较、UART打印 |
| PL compute mean | RTL start到完成的计算周期按实际PL时钟换算 | DMA/软件调度 |
| Pipelined batch | 一批图像的cache操作、独立重启两DMA通道、重叠加载与计算、全部结果收回 | 模型加载、批量图片预拷贝、结果比较、UART打印 |

流水批处理的微秒/张是**总时间除图片数的摊销时间**，不能当作每张从提交到完成的响应延迟。当前batch为随包16张图片，每张仍是一个独立DMA包。

## 3. 公平的对比方法

1. 同一模型、输入子集、编译器优化级别、CPU频率、PL频率。
2. 所有10个logit逐位相同后再对比时间。识别准确率与数值实现一致性是不同指标。
3. 记录是否包含模型加载。批量推理可摊销模型加载；冷启动实验应另外记录模型加载时间。
4. 分别报告单张延迟和批处理吞吐。不要拿批处理摊销时间冒充单张延迟。
5. 当前C参考以可读性和范围检查为目标，是scalar baseline，不是优化后的A53 NEON/CMSIS-NN性能。若用于论文或正式性能宣传，应再加入优化CPU基线。
6. 可以测到小于1的加速比。此时说明当前系统开销或RTL调度尚未优于基线，应照实记录再优化。

公式：

```text
单张加速比 = 相同CPU工作负载平均时间 / DMA+PL单张平均时间
批处理吞吐 = 图片总数 / 整批服务时间
4→16路核心周期收益 = 25863 / 21803（仅仿真计算侧）
```

## 4. 建议填写的结果表

`reports/board_results_template.csv`保留空白的真实硬件数据列。每种配置记录：LANES、PL时钟、A53频率、编译选项、测试图片数、CPU平均时间、DMA+PL平均时间、批处理吞吐、周期、LUT/FF/DSP/BRAM、WNS及PASS/FAIL。

同一套板级约束和Vivado设置下比较三种配置。尽量报告三次独立运行的均值与波动；若调整频率或编译优化，应作为新的实验行。

## 5. 下一轮优先优化

### 第一优先：MAC tap发射间隔从3周期改为1周期

当前READ→MUL→ADD确保同步RAM和乘积对齐，但每3周期才处理一个tap。引入valid流水线和末tap标志，让RAM读、乘法、累加重叠，通常比把LANES从8增加到16更有价值。需重点验证首tap偏置、末tap drain和池化边界，不能只删除两个FSM状态。

### 第二优先：窗口与权重的更有效缓存

当前同一池化区域的4个卷积窗口存在重叠像素读取。改为行缓存和窗口寄存器，降低像素RAM访问与常数除法/取模地址逻辑。FC权重可按lane重排为宽字bank，减少当前全模型复制带来的BRAM浪费。

### 第三优先：增加输出通道与分块调度

可以扩成8/16卷积通道、两个卷积层，再加入跨输入通道累加。但必须同步修改训练网络、包格式、feature buffer、量化参数与C/Python参考；不能只修改一个参数。版本升级时应改变模型包版本或ID。

### 第四优先：Scatter-Gather或更长批次

Simple DMA每张仍需要CPU提交。当前双缓冲提供第一轮数据搬运重叠；当硬件compute变快、软件提交成为瓶颈后，再增加SG描述符环或多帧包。先用暂停计数器与板上计时证明瓶颈，再增加复杂度。

现阶段可准确描述为：实现固定MNIST小型CNN的INT8 RTL推理核心，完成训练与定点导出、AXI4-Stream协议、双缓冲及逐位仿真验证，提供DMA软件与板级迁移流程。
